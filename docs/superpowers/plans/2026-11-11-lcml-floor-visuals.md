# LCML 층별 공간과 전체 보기

**Goal:** 층별 역할이 공간 자체로 구분되고 네 공간이 동시에 보이는 LCML 화면을 배포한다.
**Architecture:** 기존 React/Vite 화면과 상태 계약에 층별 이미지·좌석 메타데이터를 연결하고, 공유 OfficeScene으로 2×2 전체 보기를 그린다.
**Tech Stack:** React 18, Vite 6, CSS, imagegen PNG, 기존 S3/CloudFront.
**Spec:** `../specs/2026-11-11-lcml-office-design.md` 및 아래 사용자 보정.

사용자 보정: 사무실 비주얼이 핵심이며 같은 사무실의 반복은 요구를 충족하지 못한다. 4개 역할에 맞춘 실제로 다른 공간과 전체 층 동시 보기를 구현한다. 기존 수집·상태·인증 계약은 유지한다.

## 공간 방향

같은 바르셀로나 디자인 뮤지엄 계열 재료·등각 시점·외곽 구조를 공유하되 내부 가구·주요 설비·동선을 바꾼다.

| 층 | 공간 | 시각적 구분 |
| --- | --- | --- |
| 1F 제품실 · 지니 | 제품 개발 랩 | 세 개발 워크벤치, 서버·작업 관제, 참고 자료 라이브러리, 청회색 설비 |
| 2F 고객실 · 고딘 | 고객 리서치 스튜디오 | 원형 인터뷰 라운지, 고객 여정 전시, 리서치 워크숍 테이블, 테라코타 포인트 |
| 3F 비즈니스실 · SAM | 전략 회의실 | 긴 회의 테이블, 전략 지도·실험 자료 벽, 의사결정 자료, 짙은 월넛 |
| 4F 대표실 · 사용자 | 집무실과 정원 라운지 | 독립 집무 책상, 서재, 유리 파티션, 질문 대기 벤치, 식물과 세이지 포인트 |

새 PNG는 `dashboard/office/public/assets/floor-{product,customer,business,owner}.png`에 둔다. 실제 보드 글자와 세션은 DOM으로 올린다. 생성 이미지에 사람·임의 KPI·읽을 수 있는 설명 문구를 넣지 않는다. 층별 좌석과 보드 좌표는 자산에 맞춘다.

## 화면과 동작

- 첫 화면은 4→1층의 2×2 공간 전체 보기. 데스크톱과 모바일에서 네 공간을 한꺼번에 식별할 수 있게 한다.
- 전체 보기에서는 오른쪽 상세 패널 대신 사무실 면적을 넓게 사용한다. 각 공간에 층·역할·리더·관측 상태를 표시하며 클릭/키보드로 해당 층에 들어간다.
- 개별 층에서는 해당 전용 배경·좌석·표지·화이트보드와 기존 상세를 제공한다. 데스크톱은 긴 상세 목록과 공간 높이를 분리해 사무실 전체를 화면 안에 유지한다.
- 실제 관측 세션만 표시하며 stale 정지·이벤트 중복 억제·소등·reduced motion을 유지한다. 질문 대기자는 소속 데이터는 유지하고 시각적으로 대표실에 한 번만 표시한다. 일반 좌석과 대기 좌표를 분리한다.

## 구현·검증 기록

- 프런트엔드 회귀 테스트 27/27, Vite Office 빌드와 소스 diff 검사 통과.
- 전체 보기: 1440×900, 390×844, 320×740, 768×1024에서 서로 다른 4개 이미지가 잘리지 않고 한 viewport 안에 표시되며 가로 넘침 없음. 1440px 화면의 각 장면 크기는 약 418×279px.
- 개별 층: 1440×900·1440×1000에서 긴 고객 지표 패널과 무관하게 제목·전체 이미지·하단 조작부가 화면 안에 유지됨.
- 테스트 입력으로 네 층의 12개 세션, 질문자 대표실 이동·인원 일치, 좌석 충돌 없음, 키보드 진입, 오래된 원천의 정지, 출근→보고→퇴근 순서와 재생 중복 없음 확인. 테스트 입력은 배포 데이터에 쓰지 않음.
- 독립 검토의 대표실 좌석 충돌 및 추가로 발견한 전체 보기 질문자 중복을 수정하고 재검토에서 Critical/Important 잔여 없음.
- 네 배경은 imagegen 내장 도구로 제작했으며 원본 파일은 프로젝트 `office/public/assets/`, 전체 프롬프트는 `office/ASSET_PROMPTS.md`에 저장.
