# LCML — Less complexity, More Life

상태: 사용자 승인 및 2026-11-11 보정 반영. 기존 Status /office/, 10분 수집, 인증 없음. React/Vite 재사용. 구현 중.

## 목적과 화면

회사를 운영하는 사용자가 AI 실행 세션, 막힌 일, 고객 반응과 결정 대기 항목을 사무실 한 공간에서 이해한다. 사람 한 명은 실제 세션 하나에 대응한다. 원천에서 확인하지 못한 활동이나 수치는 만들지 않는다.

중앙에는 등각 사무실 배경 한 장을 놓고 캐릭터와 벽면 화이트보드를 별도 레이어로 배치한다. 왼쪽에는 4층→1층 순서의 엘리베이터 버튼, 위에는 LCML 이름·현재 층·관측 상태, 오른쪽에는 선택한 사람/화이트보드의 상세를 둔다. 모바일에서는 층 버튼을 하단에 두고 상세는 펼침 패널로 제공한다.

사용자 메시지의 뒤쪽에 명시된 층 구성을 우선한다. 1층은 제품실이고 별도 로비 층은 만들지 않는다. 전체 현황은 ‘전체 보기’로 제공한다.

| 층 | 리더 | 사무실과 화이트보드 |
| --- | --- | --- |
| 1F 제품실 | 지니 | OpenClaw·Infinity·Knowledge Lab의 세 업무 구역, 지니의 서브에이전트, 현재 태스크·저장소별 Git 상태 |
| 2F 고객실 | 고딘 | 프로젝트 선택, AARRR 다섯 단계, 단계별 값·기간·수집 시각·연결 상태 |
| 3F 비즈니스실 | 샘(SAM) | 전략·가치·가설, 가설별 근거·검증 상태·다음 행동 |
| 4F 대표실 | 사용자 | 결정 대기열, 질문의 대기 시간·원래 작업 링크, 당일 요약 |

## 시각 방향

바르셀로나 Disseny Hub의 금속·유리·건축적 부피에서 영감을 받아 회색 금속 프레임, 밝은 콘크리트, 큰 창, 따뜻한 목재 가구와 전시실식 사인을 사용한다. 박물관의 복제 대신 사용자가 요청한 사무실로 해석한다. LCML의 여백·읽기 쉬운 타이포그래피와 공간이 중심이며, 상태 강조색은 제한적으로 쓴다. Pretendard를 사용한다.

사무실 배경은 사람·문자 없는 단일 이미지로 제작한다. 화이트보드의 실제 글자와 수치는 DOM으로 그려 수정 가능성과 선명도를 확보한다. 캐릭터는 투명한 4열×3행 스프라이트이며, 기준 캐릭터의 이름표 색으로 구분한다. 행별 동작/프레임 좌표는 자산 메타데이터로 고정한다. 텍스트·상태 아이콘은 스프라이트 밖에 둔다.

참고: https://www.dissenyhub.barcelona/sites/default/files/press_files/press_kit_museu_del_disseny_ang_2018.pdf

## 구현 방식 비교

1. **추천: Space Status의 `/office/`에 추가.** 기존 React/Vite·정적 배포 경로와 모니터링 연결을 재사용한다. 기존 10분 수집기가 office-live.json을 함께 발행한다.
2. **독립 LCML 사이트.** 소스·배포·접근 제어를 독립시킬 수 있지만 기존 상태 수집·배포 연결을 별도로 유지해야 한다.

사용자 보정: 실시간 수집은 필요 없다. 10분마다 관측된 스냅샷으로 상태와 동작을 갱신한다. 12분은 수집 주기에 2분 여유를 둔 정체 기준이다.

## 현재 확인한 연결 지점

- 화면: `infra-aws-static-sites/sites/status/dashboard/` — React 18, Vite 6. 현재 빌드는 `../dist`로 출력한다.
- 수집기: `infra-aws-static-sites/sites/status/system-dashboard/collector/collector.py`. 이 디렉터리는 Git 하위 모듈이며 현재 gitlink보다 앞선 기존 배포 커밋이 있다. 기존 변경을 보존하고 복구 가능한 패치를 상위 저장소에 기록한다.
- 기존 공개 피드: 에이전트 종류·크론 롤업이며 개별 세션 원장이 아니다. 기존 Status는 공개 요약만 허용한다.
- 실행 원장: OpenClaw SQLite의 `subagent_runs`, `worker_session_placements`, `acp_replay_sessions` 등 존재를 확인했다. 실제 세션 상태 어댑터는 현재 런타임의 필드·종료 의미를 검증한 뒤 구현한다. 기록이 오래됐다는 이유만으로 작업 중·완료를 추정하지 않는다.
- Infinity: `/home/ubuntu/workspace/infinity/INTENTS.yaml`과 월별 archive가 현재 상태 정본이다.
- PostHog: `/home/ubuntu/workspace/monitoring_personal/posthog-exporter/index.js`는 프로젝트별 수집을 지원한다. 현재 코드에는 세션·전환·재방문 지표가 있지만 AARRR 전체가 정의·연결됐다는 증거는 없다.

## 데이터 계약과 신선도

브라우저는 30초마다 같은 출처의 상태 JSON을 요청한다. `Cache-Control: no-store`를 적용하고 동시 중복 요청은 하지 않는다. 수집기는 실제 원천을 확인했을 때만 관측 시각을 갱신한다.

- 최상위: `schemaVersion`, `sequence`, `observedAt`, `sources`, `sessions`, `questions`, `repositories`, `projects`, `strategy`, `day`.
- 세션: 안정적인 `id`, `parentId`, `agentId`, `floor`, `state`, `startedAt`, `observedAt`, 공개 가능한 `taskLabel`, 종료/결과 이벤트.
- 이벤트: 안정적인 `id`, `sessionId`, `type`, `occurredAt`. 최초 접속에 기존 세션 전부를 신규 출근으로 연출하지 않는다. 재접속·중복 JSON은 이미 처리한 출퇴근 이벤트를 반복하지 않는다.
- 질문: `id`, `sessionId`, `askedAt`, `state`, 공개 요약과 허용된 원문 링크. 원문 질문·전략·세션 대화는 기존 공개 Status에 자동 노출하지 않는다. 질문은 Infinity 원장의 승인 대기 요약을 사용하며 대화 원문은 제공하지 않는다.
- Git: 저장소별 `head`, `branch`, `dirtyCount`, 확인 가능한 `ahead/behind`, `observedAt`, 조회 오류. 매초 원격 fetch하지 않고 로컬 관측과 원격 확인 시각을 구분한다.
- 지표: 프로젝트·단계별 `value`, `unit`, `window`, `observedAt`, `state`. 0·미연결·오류·오래됨을 구분한다. PostHog는 서버에서 캐시하고 브라우저에 키를 내보내지 않는다.

세션 관측이 12분을 초과해 오래되면 캐릭터의 타자·땀·별·걷기·졸음·퇴근·조명 애니메이션을 현재 프레임에서 멈추고 ‘확인 중’을 표시한다. HTTP 200, 폴링 성공, 새 응답 생성 시각만으로 신선도를 회복시키지 않는다. 오래된 SQLite 행을 다시 읽는 것도 현재 실행의 생존 증거가 아니다. 어댑터는 런타임의 현재 run 조회·heartbeat·종료 이벤트 등 실제 확인 수단을 검증하고, 확인하지 못하면 `unknown`으로 제공한다. 부분 원천 실패는 영향을 받는 캐릭터/지표에 표시한다. 최신 증거가 들어오면 과거 이벤트를 몰아 재생하지 않고 최신 상태로 복귀한다.

Git·PostHog는 세션과 다른 수집 주기를 가지며 각각의 마지막 관측 시각을 보여준다. 오래된 지표가 세션을 살아 있는 것으로 만들지 않고, 반대로 느린 분석 지표 때문에 최신 세션까지 멈추지 않는다.

## 동작

- 층 이동: 위·아래 방향에 맞는 수직 슬라이드. 층 번호와 선택 상태를 동시에 갱신하고 빠른 연속 클릭은 최종 목적지로 수렴한다.
- 작업 중: 타자 프레임. 실행 시작 이후 40분 초과 또는 명시적 막힘이면 땀 표시.
- 결과 보고: 실제 결과 이벤트에만 만세·별을 한 번 재생한다. 실패 종료는 완료 축하로 바꾸지 않는다.
- 대기: 실제 대기 상태에서 커피·졸음. 리더라도 실행 세션이 없으면 이름표만 남고 가짜 사람을 생성하지 않는다.
- 하위 세션 시작/종료: 새 이벤트에서만 엘리베이터→자리 또는 자리→엘리베이터 경로로 걷고 ‘출근합니다!’/‘퇴근합니다!’를 표시한다. 목록에서 사라짐만으로 정상 퇴근을 판정하지 않는다.
- 질문 대기: 대표실 앞에서 `askedAt` 순으로 줄 선다. 오래 기다린 모습은 원천 대기 시간에 기반하며, 기본 제안은 10분 이후 쪼그림·40분 이후 땀이다. 사용자 변경 가능 설정으로 둔다.
- 하루 마감: `day.phase=closing|closed`과 `closedAt` 근거가 있을 때 방별로 차례로 불을 끈다. 실행 중이거나 질문 대기인 방은 남긴다. 사용자 시간대와 마감 설정을 사용하며, 미설정 상태에서 임의 시간에 소등하지 않는다.
- 접근성: 키보드 층 이동·명확한 포커스·상태 텍스트·44px 이상 터치 영역. `prefers-reduced-motion`에서는 이동/몸짓 없이 상태를 즉시 반영한다.

## 구현·배포 경계

정적 UI와 자산은 Space 정적 사이트 경로에 둔다. 기존 컬렉터가 같은 S3 버킷의 office-live.json을 10분마다 갱신한다. 별도 Next.js·API 서버는 필요 없다. 개발 환경은 동일 JSON 계약을 localhost 정적 서버에서 제공한다.

원천별 연결 상태를 화면에 표시한다. 샘플 데이터는 개발 검증용으로만 사용하며 라이브 화면의 실측으로 표시하지 않는다. 사용자가 인증 없음으로 승인했으며, 기존 공개 도메인의 운영 요약으로 배포한다.

접근 제어: 사용자가 개인 인증 불필요를 명시했다. /office/는 기존 Status와 동일하게 인증 없이 접근한다. 브라우저 응답은 필요한 상태·명시적인 운영 문서 요약에 한정하고 토큰·원문 대화·개인 연락처는 포함하지 않는다.

## 검증·완료 조건

1. 4층 이동 방향·빠른 전환·모바일 터치·키보드 동작 확인.
2. 스프라이트 4×3 좌표·배경 정렬·벽면 화이트보드 실제 렌더 확인.
3. 실행/40분 경과/막힘/보고/대기/출근/퇴근/대기열/소등의 근거별 전환 검증.
4. 12분 초과, 동일 JSON 반복, 원천 실패, HTTP 오류, 시계 이상, 재접속에서 거짓 움직임·이벤트 중복이 없는지 검증.
5. Git 상태는 실제 저장소와 대조. AARRR은 프로젝트별 정의·기간·값·미연결 상태를 확인.
6. 공개 응답에 세션 원문·질문 원문·시크릿·사적 전략이 없고, 운영 요약만 포함하는지 확인.
7. 데스크톱·390px 화면, reduced-motion, 자산 로드 실패 확인 후 build·소스 diff·원격 반영·라이브 URL을 각각 검증.
