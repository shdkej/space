- 층별 실제 태스크 요약, 세 저장소 Git, 프로젝트별 AARRR 선택, 전략/가치/가설, 질문 대기열·질문 티켓·대기 표현 설정, 전체 보기.
- 관측 세션 스프라이트, 출퇴근/보고 이벤트 중복 방지, 경과/막힘의 땀, 대기 커피/졸음, 근거 있는 소등, 리더 역할 이름표.
- 30초 no-store 폴링, 720초 신선도 경계, 원천 오류·HTTP 실패 시 정지, 오류/빈 상태/이미지 실패, 실제 0과 미측정 구분.
- 키보드 이동, reduced motion, 모바일 하단 층 선택, 층별 가구에 맞춘 좌석과 전체 세션의 상세 목록.

## 층별 비주얼 수정 — 2026-11-11

사용자가 동일한 사무실 반복을 수정 요청했습니다. 최초 단일 배경과 텍스트 전체 보기 대신 제품 랩·고객 리서치·전략 회의·대표 집무실의 네 PNG를 사용합니다. 자산은 통합 담당자가 생성했고 화면 담당자가 네 원본을 직접 열어 보드·좌석·대표실 대기 벤치·존 표지를 맞췄습니다.

기본 화면은 4·3 / 2·1의 2×2 실제 공간 전경입니다. 우측 상세를 숨겨 공간 면적을 넓혔고 전경과 개별 층에 같은 세션·보드·조명 컴포넌트를 사용합니다. 전경 내부는 비대화형 DOM, 층 진입은 별도 버튼으로 구성했습니다. 전체 보기 상단에 특정 층 번호나 리더를 표시하지 않습니다.

소등 마스크는 건물 외곽으로 제한합니다. 네 구역의 순차 소등·stale 정지·reduced motion, 최초/중복/복구 이벤트 재생 방지와 세션별 순차 이벤트는 유지합니다.

## 확인한 증거

- `node --test office/test/*.test.*`: 27/27 통과. 기존 상태 회귀 테스트와 실제 React 렌더 검증에 네 자산·네 진입 버튼·관측 세션·실제 보드의 전체 보기 테스트를 추가했습니다. 새 전체 보기 테스트와 대표실 혼합 좌석·다른 층 질문자의 중복 표시 테스트에서 실패→통과를 확인했습니다. 질문자는 원천 소속을 보존하고 대표실 대기열에 한 번만 렌더합니다. 공통 occupancy 계산으로 전경·장면 설명·하단 숫자·세션 목록에 같은 공간별 인원을 표시합니다.
- `npm run build:office`: Vite 6.4.5 성공, 경고 없음. 최신 빌드 JS 약 183.3 kB / gzip 59.2 kB, CSS 약 34.6 kB / gzip 7.7 kB. 4개 PNG가 `dist/office/assets/`에 함께 복사됩니다.
- `git diff --check`: 통과.
- 통합 담당자가 1440×900, 390×844, 320×740, 768×1024에서 네 이미지·층명 동시 표시와 가로 넘침 없음을 확인했습니다. 그 후 데스크톱 상하 여백 축소와 건물 외곽 소등 마스크를 추가했습니다. 최종 브라우저·라이브 검증은 통합 단계가 담당합니다.
- 실제 Chrome에서 긴 고객실/비즈니스실 상세 fixture를 사용해 1440×900·1440×1000의 네 개별 층 모두 제목·이미지 전체·하단 조작부가 화면 안에 있음을 확인했습니다. 900px 화면 이미지 경계는 y=231–809, 1000px 화면은 약 y=233–909이며, 상세를 스크롤해도 장면 경계가 유지됐습니다.
- 대표실 일반 좌석 3개와 질문 벤치·줄 좌표는 서로 겹치지 않습니다. 기존 전체 보기 치수와 모바일 개별 층 스크롤은 변경하지 않았습니다.
- 이번 화면 수정 담당자는 commit/push/deploy를 실행하지 않았습니다.
