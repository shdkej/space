# LCML Office

LCML은 회사의 실행 세션과 결정 대기 항목을 네 층의 사무실로 보여주는 읽기 전용 화면입니다. 제품실(지니), 고객실(세스고딘 CMO), 비즈니스실(SAM), 대표실(사용자)의 책임을 구분합니다. 현재 등록된 OpenClaw 에이전트 7명과 대표 자리는 쉬는 동안에도 사람으로 표시합니다. 실행 세션은 해당 인물의 상태에 연결하고 하위·동시 실행은 추가 작업자로 표시합니다. 첫 화면은 4→3→2→1층이 하나의 골조 안에 세로로 연결된 건물 단면입니다. 각 층을 누르거나 키보드로 선택하면 해당 층의 큰 장면과 상세로 들어갑니다.

## 실행과 검증

기존 `dashboard/`의 React 18 / Vite 환경을 재사용합니다. 추가 패키지는 없습니다.

```sh
cd /home/ubuntu/workspace/space/infra-aws-static-sites/sites/status/dashboard
node --test office/test/*.test.*
npm run build:office
npx vite --config vite.office.config.js
```

빌드는 `../dist/office/`만 교체합니다. 배포는 상위 Status README의 기존 S3/CloudFront 경로를 사용합니다. 로컬 정적 확인은 `../dist/`를 HTTP로 제공하고 `/office/`를 엽니다. 개발 Vite 서버에는 별도로 같은 출처의 `/office-live.json`이 필요합니다. 실행 환경의 자격증명이나 수집 원천에 브라우저가 직접 접근하지 않습니다.

## 데이터와 화면

- `/office-live.json`: schemaVersion 1. 10분 수집, 브라우저 30초 확인, 요청 12초 제한, 중복 요청 방지, no-store.
- `residents`는 등록 명단, `sessions`는 실행 관측입니다. `sources.residents`, `openclawSessions`, `codexSessions`를 구분하고 부분 실패를 표시합니다. 등록 조회 실패 때 마지막 명단과 원래 관측 시각을 보존합니다.
- 세션 provider별 source.state와 실제 관측 시각을 함께 확인합니다. 마지막 관측이 720초를 넘거나 원천이 실패하면 마지막 캐릭터 프레임을 정지합니다. 층 이동은 계속 가능합니다.
- 세션별 이벤트 큐가 같은 수집 구간의 도착·보고·퇴근을 순서대로 보여주고 마지막 이벤트가 끝나면 추가 작업자를 제거합니다. 상주 인물은 도착·퇴근하지 않고 작업이 끝나면 원래 자리에서 쉽니다. 결과 보고만 실제 이벤트에 연결합니다. 최초 접속·중복 스냅샷·과거 스냅샷·오류 복구에서 과거 출퇴근/보고 이벤트를 재생하지 않습니다. 세션 목록에서 사라졌다는 이유만으로 퇴근 이벤트를 만들지 않습니다.
- Git은 로컬 관측과 원격 추적 브랜치 기준입니다. AARRR은 프로젝트 선택, 값·단위·기간·수집 상태와 원천 설명을 보여줍니다. 태스크·Git·지표도 실제 관측 시각 720초를 기준으로 신선도를 표시합니다. AARRR 단계별 관측 시각을 별도로 보여줍니다. 미측정·현재 확인 불가 값은 `—`, 신선하게 측정된 0은 `0`입니다.
- 대표실 질문은 오래 기다린 순서입니다. 연결된 세션이 없으면 사람 대신 질문 티켓으로 표시합니다. 자세 변경 10분/땀 40분 기본값은 대표실 상세에서 변경할 수 있습니다.
- 화면상의 세션 좌석은 각 층 이미지의 실제 가구에 맞춰 제품실 8개, 고객실 12개, 비즈니스실 8개, 대표실 3개를 둡니다. 대표실 질문 세션은 일반 좌석과 분리된 벤치·줄에 최대 8개를 표시합니다. 질문에 연결된 세션은 원래 층의 일반 자리에서 제외하고 대표실 대기열에 한 번만 표시합니다. 원천의 소속 층 값은 변경하지 않습니다. 전경·장면 설명·하단 숫자·세션 상세 목록은 현재 표시 공간의 일반 세션과 대표실 질문 대기자를 함께 집계합니다. 좌석 수를 넘는 세션도 이 집계와 상세 목록에 포함합니다. 모든 인물은 우측 ‘이 공간의 사람들’ 목록에서 상세를 열 수 있습니다. 상주 인원·대표 자리·확인된 실행 세션 수·미확인 세션 수는 구분합니다. 일부 원천이 실패하거나 개별 활동이 오래되면 과거 작업을 현재 실행 합계에 넣지 않습니다.
- `day.phase=closing|closed`와 `closedAt` 근거가 있을 때 소등합니다. 작업·대기·막힘·보고·미확인 세션 또는 질문이 있는 방은 켜둡니다. 새로운 열림→마감 관측에서만 네 구역이 차례로 어두워집니다. 조명 레이어는 건물 외곽으로 잘라 배경 여백을 어둡게 하지 않습니다. 첫 관측부터 닫힌 상태면 소등 과정을 재생하지 않습니다. 브라우저가 임의로 마감 시각을 정하지 않습니다.
- 밝기는 전체 건물과 개별 층에 같은 CSS 보정을 적용합니다(`brightness(1.1) contrast(.97)`). 소등은 최대 7%의 은은한 음영으로 표현해 쉬는 시간에도 인물과 공간이 보이게 합니다. 글자·화이트보드·캐릭터 원본에는 밝기 필터를 적용하지 않습니다.
- `prefers-reduced-motion`, 키보드 층 이동(위/아래/Home/End), 포커스, 모바일 하단 층 선택을 지원합니다.

## 이미지 계약

층별 공간은 각각 다른 1536×1024 PNG입니다. 같은 외곽 시점·엘리베이터·뒤쪽 왼쪽 보드를 공유하며 내부 가구와 주요 설비는 다릅니다.

건물 단면 `public/assets/building.png`(1024×1536)과 네 개별 층 배경은 imagegen 내장 도구로 제작했습니다. 자산별 전체 제작 프롬프트와 저장 경로는 [ASSET_PROMPTS.md](ASSET_PROMPTS.md)에 보관합니다.

| 층 | 자산 | 공간 |
| --- | --- | --- |
| 제품실 | `public/assets/floor-product.png` | 개발 워크벤치 · 서버 관제 · 자료 라이브러리 |
| 고객실 | `public/assets/floor-customer.png` | 원형 인터뷰 라운지 · 고객 여정 전시 · 리서치 워크숍 |
| 비즈니스실 | `public/assets/floor-business.png` | 긴 전략 회의 테이블 · 자료 벽 · 아카이브 |
| 대표실 | `public/assets/floor-owner.png` | 독립 집무 책상 · 서재 · 정원 라운지 · 질문 대기 벤치 |

`src/model.js`의 `FLOORS[].visual`이 각 자산·대체 텍스트·색·보드·좌석·엘리베이터·존 표지 좌표를 소유합니다. 좌표는 원본 전체 이미지 기준 백분율입니다. 네 자산을 직접 확인해 좌석을 맞췄습니다. 이전 `office.png`는 이전 버전 참고 자산이며 현재 화면에서 사용하지 않습니다.

전체 보기는 하나의 건물 이미지 위에 층별 인물·화이트보드·진입 영역을 겹칩니다. `BUILDING` 좌표는 건물 원본의 백분율이고, `FLOORS[].visual`은 개별 층 좌표입니다. 두 화면은 같은 인원 계산과 상태·스프라이트를 공유합니다. 전체 보기의 보드·캐릭터는 비대화형 DOM이며 층당 하나의 진입 버튼을 제공합니다. 데스크톱은 건물 오른쪽에 층 안내를, 모바일은 엘리베이터 쪽에 작은 층 표지를 둡니다. 모바일 전체 보기는 `100dvh`에서 상단 상태·하단 메뉴·안전 영역을 제외한 공간에 건물을 비율대로 맞춰 네 층을 스크롤 없이 보여줍니다. 낮은 가로 화면은 상태·메뉴와 건물을 좌우로 나눕니다. 수집 오류 안내가 생겨도 남은 높이를 다시 계산합니다. 개별 층의 상세 패널과 기존 스크롤 동작은 유지합니다. 작은 벽면 글자의 전체 내용은 개별 층 상세에서 읽습니다.

`public/assets/characters.png`는 4열×3행 투명 스프라이트입니다. 열/행 좌표는 0부터 시작합니다.

| 행 | 열 | 상태 |
| --- | --- | --- |
| 0 | 0–3 | 타자 프레임 |
| 1 | 0–1 | 걷기 |
| 1 | 2 | 보고 자세 |
| 1 | 3 | 서서 커피 |
| 2 | 0–1 | 앉아서 커피 / 졸음 |
| 2 | 2 | 오래 기다리는 자세 |
| 2 | 3 | 중립 자세 |

이름표 색으로 세션을 구분하며 피부색은 변경하지 않습니다. 별과 땀은 별도 DOM입니다. 상주 리더는 실행이 없어도 커피·휴식 자세로 남습니다. 실행 원천을 확인하지 못했으면 마지막 자세를 정지하고 확인 중으로 표시합니다. 대표는 정적인 자리 표시이며 사람의 온라인 상태를 추정하지 않습니다.

## 운영 경계

로그인 없는 기존 Status의 `/office/` 경로이며, 공개 가능한 요약만 수집기가 공급해야 합니다. UI에는 샘플 데이터나 폴백 가상 세션이 없습니다. 상주 명단은 현재 OpenClaw 등록 원천에서 수집하며 실행 세션과 구분합니다. Codex는 로컬 SQLite의 최신 turn 및 같은 turn의 활동 시각 메타데이터만 읽습니다. 테스트 fixture는 테스트 코드 안에만 있습니다. 세션 생존 판정·질문 공개 요약·지표 정의의 정확성은 수집기 계약에 의존합니다. 프로젝트 설정에 정의된 AARRR이 없으면 화면에서 새 지표를 만들어 채우지 않습니다.

원천 수집과 배포 방법은 상위 [Status README](../../README.md), 수집기 계약은 승인된 [구현 계획](../../../../../docs/superpowers/plans/2026-11-11-lcml-office.md)을 참고합니다.

## 사무실만 배포하기

사무실 변경은 `main`의 이 소스에서 `npm run build:office`로 만든 `dist/office/`를 배포합니다. 다른 Status 화면이 별도 작업 중이거나 운영본과 다르면 전체 버킷 동기화 대신 아래 범위를 사용합니다. 기존 해시 자산을 남겨 이전 HTML로 되돌릴 수 있습니다. AWS 계정과 도메인의 배포 대상을 먼저 확인합니다.

```sh
cd /home/ubuntu/workspace/space/infra-aws-static-sites/sites/status
aws s3 sync dist/office/ s3://static-status-aws-shdkej-com/office/ --cache-control 'public,max-age=60'
aws s3api put-object --bucket static-status-aws-shdkej-com --key 'office/' --body dist/office/index.html --content-type text/html --cache-control 'public,max-age=60'
aws cloudfront create-invalidation --distribution-id E9GKZBY9S3VTW --paths '/office/*' '/office/'
```

배포 후 `/office/`와 `/office/index.html`, 참조 JS·CSS의 HTTP 응답과 로컬 SHA256을 비교합니다. 모바일 세로·가로에서 문서 높이=뷰포트 높이, 네 층과 메뉴의 화면 내 경계, 층 진입·전체 보기 복귀, 오류 안내를 확인합니다. 기기 자체 Safari 주소 막대 동작은 별도 실기기 확인 대상입니다.
